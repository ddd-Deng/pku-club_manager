# AI 辅助开发流程（前端）

> 面向团队「AI 辅助开发计划」章节。说明本项目前端如何把 AI（Claude / AiWork 等代码助手）用在真实开发流程里：
> 规则约束 → 分步生成 → 代码审查 → 人工验收 → 提交归档。

## 1. 总体原则

| 原则                | 说明                                                                                |
| ------------------- | ----------------------------------------------------------------------------------- |
| 人定契约，AI 写实现 | 页面结构以 Xmind 为准，接口以 `docs/api.md` 为准；AI 不得自行发明字段、路径或状态码 |
| 小步生成            | 一次只让 AI 做一件事（一个页面 / 一个模块 / 一个组件），产出可评审、可回滚          |
| 规则前置            | 每次对话都把 `CLAUDE.md` 作为规则输入，避免风格漂移与越界改动                       |
| 人必须验收          | AI 产出视为「初稿」，未经人工运行验证不得合并                                       |
| 前端边界            | AI 只写前端代码；后端 / 数据库 / AI 模型逻辑只写契约与 mock                         |

## 2. 规则文件（AI 的"输入约束"）

| 文件                                                      | 作用                                                                                           | 使用方式                                                   |
| --------------------------------------------------------- | ---------------------------------------------------------------------------------------------- | ---------------------------------------------------------- |
| `CLAUDE.md`                                               | 前端开发硬规则：技术栈、目录命名、数据层调用规范、三态处理、样式变量、TS/ESLint 约束、禁止事项 | 每次开新会话时作为系统规则或首个上下文提供                 |
| `docs/api.md`                                             | 前后端接口契约（method / path / 参数 / 响应示例 / 角色 / 错误码）                              | 涉及数据请求的任务必须附带相关章节                         |
| `README.md`                                               | 项目现状、路由与页面实现状态、启动与验证方式                                                   | 让 AI 了解"哪些已做、哪些是占位"                           |
| `docs/ui/xmind-structure.jpeg`                            | 页面结构、页面内组件、页面跳转出口（权威）                                                     | 做页面设计时提供，AI 按图拆分组件                          |
| `docs/ui/ui-*.png`                                        | UI 稿（文字有乱码，仅供布局 / 配色 / 风格参考）                                                | 做视觉还原时提供，明确"不参考文字"                         |
| `eslint.config.js` / `.prettierrc.json` / `.editorconfig` | 机器可执行的规则                                                                               | 由 `npm run lint` / `npm run format` 兜底，AI 产出必须通过 |

## 3. 分步生成流程

以「实现社团详情页」为例，标准五步：

1. **明确输入**
   向 AI 提供：`CLAUDE.md` 全文 + `docs/api.md` 第 4.4 节（社团详情接口）+ Xmind 中网页 3 的组件与跳转出口 + 对应 UI 稿。
2. **让 AI 先出方案再写码**
   要求先输出：组件拆分、数据来源（调用哪个 api 函数）、路由与跳转、三态处理方式、需要新增的类型 / mock。人工确认方案后再写代码。
3. **生成代码**
   按方案生成 `src/views/club/ClubDetailView.vue` 等文件；接口缺失时先在 `src/types` / `src/api` / `src/mock/handlers` 补齐，禁止在页面写死假数据。
4. **自查清单**（AI 生成后自己逐条核对）
   - [ ] 是否只调用 `src/api/*`，没有直接 import axios / mock / 写 URL
   - [ ] 是否有加载中 / 空数据 / 失败三态，失败态带"重新加载"
   - [ ] 字段是否与 `docs/api.md` 完全一致
   - [ ] 命名是否符合规范（组件 PascalCase、目录路由 kebab-case、函数 camelCase）
   - [ ] 颜色圆角是否使用 CSS 变量
   - [ ] 有无 `any`、有无未使用变量、有无 `eslint-disable`
   - [ ] 路由 meta 权限（`requiresAuth` / `roles`）是否正确
5. **本地验证**
   `npm run lint`、`npm run type-check` 零报错，`npm run dev` 手工点检页面与跳转。

> 提示：单次任务过大（如"把整个管理后台做完"）会让 AI 产出难以评审，应拆成 6 个标签分区分别生成。

## 4. 代码审查（AI + 人）

### 4.1 AI 自审 / 互审

- 让 AI 以「审查者」角色重新读取 diff，按 `CLAUDE.md` 第 7 节禁止事项逐条挑问题，输出：问题清单 + 严重级别 + 修改建议，不直接改代码。
- 可让另一个会话（不带生成上下文）做交叉审查，减少"自证正确"偏差。
- 审查重点顺序：契约一致性 > 权限与登录态 > 三态与错误处理 > 命名与目录规范 > 样式变量 > 冗余代码。

### 4.2 人工审查

- 逐文件看 diff，重点确认：接口路径与字段、路由权限、mock 是否与契约一致、有无偷偷改公共文件（`request.ts`、`types/common.ts`、`variables.css`）。
- 机器检查为准：`npm run lint`、`npm run type-check`、`npm run build` 必须通过，不接受"看起来没问题"。

## 5. 人工验收

| 验收项          | 方法                                                                                      |
| --------------- | ----------------------------------------------------------------------------------------- |
| 能跑起来        | `npm install && npm run dev`，首页与目标页可正常打开                                      |
| 数据来自 api 层 | 断网或改 mock handler 抛错，页面应出现失败态而非白屏 / 假数据                             |
| mock 可切换     | `VITE_USE_MOCK=false` 重启，页面代码不变，失败态提示网络异常                              |
| 权限正确        | 用 student / clubAdmin / admin 三个演示账号分别访问受限页面，验证跳转与提示               |
| 三态齐全        | 制造加载中（mock 有 200~500ms 延迟）、空数据（搜索无结果）、失败（关掉后端）三种场景      |
| 视觉符合 UI 稿  | 与 `docs/ui/` 对照布局、配色（蓝白）、卡片圆角；文案以 Xmind 为准，不以 UI 稿乱码文字为准 |

验收不通过的条目写成 issue 反馈给 AI 迭代，一次只改一个问题点。

## 6. 提交与归档

- commit 前缀：`feat` / `fix` / `docs` / `refactor` / `style`，中文描述，例：`feat: 实现社团详情页与入社申请`。
- 接口契约变更与前端代码**同一次提交**，保证 `docs/api.md` 与实现同步。
- 每次迭代结束更新 `README.md` 的「页面与路由」实现状态表（✅ / ⏳）。

## 7. AI 使用边界与风险

| 风险                    | 应对                                                               |
| ----------------------- | ------------------------------------------------------------------ |
| AI 编造接口字段 / 路径  | 强制以 `docs/api.md` 为唯一契约，审查时逐字段核对                  |
| AI 越界写后端代码       | `CLAUDE.md` 明确禁止；审查时检查是否出现服务端逻辑、数据库操作     |
| AI 为通过 lint 关闭规则 | 禁止新增 `eslint-disable`，出现即打回                              |
| AI 输出大段不可评审代码 | 任务拆小；单文件超过 ~300 行要求拆分组件                           |
| 依赖膨胀                | 新增依赖需说明理由并人工确认，优先复用 Element Plus 能力           |
| 幻觉式"已完成"          | 一切以本地实际运行结果（lint / type-check / build / 手工点检）为准 |
